Evidence before confidence.

A city research workspace that turns live public sources into a source-traceable brief — and refuses to publish anything it cannot quote.

FastAPILangGraphSQLite ledgerQdrantGraphiti + Neo4j SandboxStatic frontend

System context

One deployed service. The frontend, the orchestration graph and the API share a process; all durable knowledge lives outside it, because the free hosting tier has ephemeral disk and sleeps when idle.

Agent workflow

Responsibility is split so that no agent can both produce a claim and bless it. Two stages are gates rather than steps: they can remove work from the pipeline, and what they remove is recorded rather than discarded.

The trust rule, stated once: no source quote means no published fact, and no verified evidence means the answer says the evidence is insufficient. Every refusal is written down where the user can see it.

Data architecture

Three stores because three questions are genuinely different in shape: what happened in this run, what text is semantically near this question, and what is connected to what. Forcing all three into one store makes two of them slow and one of them lossy.

StoreWhat lives hereWhy this storeRead at
RelationalSQLite → PostgreSQL Research runs, discovered sources, crawl decisions, verified facts, knowledge gaps, guardrail outcomes, stage traces, run metrics. This is the audit record. It needs exact reads, stable ordering and a schema, not similarity. It is also the only store that can answer “what did the system decide, and when”. History, report, admin view
VectorQdrant Cloud Evidence passages with their full fact payload — claim, quote, source URL, scope, verification status. A City Lead asks questions in their own words, not in the words of the source. Payload filtering by research city keeps one city’s evidence out of another city’s answer. Every question
GraphGraphiti + Neo4j Sandbox Entities and their relationships — organisations, programmes, policies, places — grouped per city and timestamped by Graphiti. “Who runs what, and how does it connect” is a traversal, not a search. Graphiti also gives the memory a time dimension, so a city can be re-researched later without overwriting what was true before. Graph view, entity context

Retrieval strategy

  1. Scope first. A question is always bound to one researched city before anything is retrieved, so evidence cannot leak between cities.
  2. Vector recall. The question is embedded and matched against city-filtered evidence passages in Qdrant.
  3. Ledger fallback. If the vector store is unavailable or empty, term overlap against verified facts in the relational ledger takes over, so the demo degrades instead of failing.
  4. Graph context. The relationships around the city are fetched from Neo4j and returned alongside the answer, so the user can see structure as well as text.
  5. Refuse cleanly. If nothing verified matches, the system returns an explicit insufficiency response and does not infer.

Key design decisions

Decision 01

Crawlability is a gate, not a filter

robots.txt is read before the first fetch, not after. A disallowed source still appears in the UI with its refusal reason, so the user can follow it manually. Politeness is visible rather than silent.

Decision 02

Gaps are a first-class output

A withheld claim is not a failure to hide. It is written to the gap ledger with its topic, reason and URL and shown next to the findings, because a City Lead needs to know what they still have to ask about in the room.

Decision 03

Scope is carried on every fact

National figures presented as city figures are the most likely way this system could mislead. Every record carries an explicit geographic scope field, and unresolved scope is flagged rather than quietly assumed.

Decision 04

Provider failure is surfaced, not swallowed

When a datastore or LLM provider is unavailable the run continues, the store reports its real state in the admin view, and /api/provider-check gives a sanitised diagnosis without returning credentials.

Trade-offs and what was cut

  • Research breadth was capped deliberately. A small number of topic queries and a small number of extracted sources per run keeps the end-to-end loop demonstrable inside the timebox. Depth is a tuning problem; the pipeline shape is the hard part.
  • SQLite over managed PostgreSQL. Zero setup for the case study, and the schema is portable. Local disk on the free tier is ephemeral, so this is explicitly not production storage.
  • No human review step. The design question “should humans review before storage” was answered as not yet: the fact-check gate plus a visible gap ledger gives most of the safety, and a review queue would have consumed the remaining time.
  • Single search provider. A second, independent discovery source would improve both recall and resilience, and is the first thing to add.
  • Conflict handling is unmodelled. Two sources that disagree currently both appear with their quotes. Detecting and adjudicating contradiction is real work and was consciously deferred.
  • Free hosting sleeps. First request after idle is slow. Acceptable for evaluation, not for a City Lead on a deadline.
Known limitations in this build
  • Claim extraction is shallow. Findings are currently source-level rather than statement-level, so the brief tells you which sources are relevant more strongly than it tells you what they say. Grounded, quote-anchored claim extraction is the highest-value next change.
  • Verification is rule-based. The fact-check gate enforces quote presence, health context and city-scope sanity. It is independent of the producing stage and it does withhold, but it reasons about evidence shape rather than evidence meaning.
  • Graph retrieval is read-only context. Neo4j is queried live for the graph view; folding traversal results into the answer path is designed but not yet wired into /api/ask.

How quality is measured

The admin view is part of the argument, not a debug panel. It reports source discovery and crawl approval counts, extraction success, evidence coverage, city-scope quality, verified versus withheld facts, gap count, provider errors, guardrail outcomes and per-stage durations — so a claim about trustworthiness can be checked rather than believed.
