Evidence before confidence.

A city research workspace that turns live public sources into a source-traceable brief — and refuses to publish anything it cannot locate in a source and have independently checked.

System context

One deployed container serves the API and the frontend. Every model call goes through a single boundary that owns pacing, failover and fallback. Durable knowledge lives in hosted stores, because the free hosting tier has an ephemeral disk and sleeps when idle.

Agent workflow

Ten LangGraph nodes, each with one responsibility. GET /api/workflow renders the structure from the compiled graph, so the diagram in the UI cannot drift from the code that runs. Three nodes are gates: they remove work, and what they remove is recorded as a gap.

The trust rule, stated once: no located quote means no claim, no independent verdict means no publication, and no verified evidence means the answer says the evidence is insufficient. Every refusal is written down where the user can see it.

How fabrication is prevented

The guarantees that matter most do not depend on a model behaving well. They are string and number checks that run before or instead of a model call — which also makes them the cheapest part of the pipeline.

Guard 01 · grounding

Quotes must exist in the source

The extractor's quote is located in the full document text. The span stored is the one found in the document, not the one the model wrote. A quote that cannot be located is discarded and counted.

Guard 02 · numeric

Figures must appear in the evidence

Any number in a claim that is absent from its quote makes the claim UNSUPPORTED immediately, with no model opinion involved. This is the “never invent statistics” rule, enforced.

Guard 03 · independence

The checker is never the extractor

The fact checker is chosen from models other than the one that extracted the claim, uses an adversarial prompt, does not see the extractor's reasoning, and returns a schema-constrained verdict including scope.

Model routing

No single model is right for every job. Work is routed by what it needs — long-document reading, short structured verdicts, or bursty graph extraction — and each role gets its own tokens-per-minute budget. Deployed configuration from render.yaml:

Throughput and resilience on free tiers

A free generation tier is not unreliable so much as tightly metered. Most of the engineering in the model boundary exists to spend each per-minute window on work rather than on rejected requests — and to never pass off a degraded result as a full one.

  1. Shared cooldown per model. The first 429 sets a resume time every caller for that model honours. Without it, concurrent callers backed off separately and collided again — once 75 rejected requests to land 16.
  2. Failover, not waiting. A throttled extraction call moves to the pool model that is free soonest rather than queueing behind the throttled one.
  3. A time budget, not a retry count. Throttled calls retry for up to 300 s using the provider's retry-after. Giving up after three collisions used to drop most fact checks to the weaker rules path in a busy round.
  4. Rate limit is not an outage. Throttling and exhausted quota raise the same SDK exception; they are told apart by the structured error code. Matching words once turned Groq's “billing” upgrade link into a terminal outage.
  5. Half-open circuit breakers. A terminal error opens the circuit so a dead key costs one call, not one per document; after 120 s a single probe lets a fixed key recover without a restart. Chat and embeddings fail independently.
  6. Fallbacks are counted. Facts checked by rules instead of the model raise a guardrail warning and appear in the run metrics.

Data architecture

Three stores because three questions are genuinely different in shape: what happened in this run, what text is semantically near this question, and what is connected to what. Forcing all three into one store makes two of them slow and one of them lossy.

Retrieval strategy

  1. Scope first. A question is bound to one researched city before anything is retrieved, so evidence cannot leak between cities.
  2. Vector and graph concurrently. Qdrant for semantic recall over verified evidence, graphiti.search() for relationship facts in the city's subgraph.
  3. Ledger fallback. When fewer than three items come back, term matching over the relational ledger tops up the evidence, so retrieval degrades instead of disappearing.
  4. Synthesis from numbered evidence. The fast model must cite evidence numbers; the API resolves them back to stored records, and national evidence must be labelled as national in the sentence that uses it.
  5. Refuse cleanly. No verified match returns an explicit insufficiency answer and the related gaps, not an inference.

Graceful degradation

Configuration is not capability. GET /api/runtime reports what the system can actually do right now, and the UI shows a banner when it is running reduced.

Trade-offs and what was cut

  • Research depth is a user choice. Quick (5 sources, one round, ~1–2 min), Balanced (8 sources, optional smaller second round, ~2–4 min), Thorough (12 sources, ~4–8 min). Estimates are measured on Groq's free tier and shown as approximate.
  • SQLite over managed PostgreSQL. Zero setup and a portable schema. Local disk on free hosting is ephemeral, so history resets on restart; the vector store and graph persist.
  • No human review step. The fact-check gate plus a visible gap ledger gives most of the safety for a fraction of the time.
  • Open-weights models on a hosted free tier rather than a paid frontier API or a local model. Zero cost and no vendor lock-in, paid for with rate limits — which the model boundary is built around.
  • Discovery through APIs, not scraped search. Search engines serve captchas to non-browser clients, and scraping them sits badly beside a crawl-permission gate.
  • Free hosting sleeps. The first request after idle is slow. Acceptable for evaluation, not for a City Lead on a deadline.
Known limitations in this build
  • Conflicting sources are not adjudicated. Two sources that disagree both appear with their quotes.
  • No OCR. PDFs are read (capped at 60 pages / 12 MB); a scan without a text layer is recorded as needing OCR.
  • The graph reranker is a bi-encoder. Cosine similarity on embeddings is less precise than a cross-encoder, chosen because it runs on any embedding endpoint.
  • The graph lags the brief. It is built in the background and capped at eight episodes per run, so relationships appear a few minutes after findings.
  • No authentication or multi-tenancy. Required before real use.

How quality is measured

The runtime view is part of the argument, not a debug panel. Each run reports sources discovered, crawl-approved and refused, sources read, candidate versus verified claims, withheld and scope-flagged facts, facts checked by model versus rules, claims extracted by model versus heuristically, dimension coverage, city-scope quality, mean confidence, provider errors, guardrail outcomes and per-stage durations — so a claim about trustworthiness can be checked rather than believed.
